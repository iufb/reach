# 0007. Регистрация новых аккаунтов — по возможности

- Статус: принято
- Дата: 2026-11-20

## Контекст

Риск из PRODUCT.md §10: Telegram может ограничивать создание аккаунтов через сторонние клиенты (#28). Что известно из официальной документации (core.telegram.org):

- `auth.sendCode` может вернуть `PHONE_NUMBER_APP_SIGNUP_FORBIDDEN` («You can't sign up using this app»): сервер отказывает в регистрации нового номера для конкретного `api_id`.
- Для части номеров код по SMS/звонку доступен только через Firebase SMS — то есть только официальным мобильным приложениям (`api/auth`). Сторонним приложениям остаются другие способы доставки; для SMS можно написать на sms@telegram.org.
- Прямого запрета на `auth.signUp` (в TDLib — `registerUser`) для сторонних приложений документация не содержит; ошибки `auth.signUp` — только про имя, код и занятый номер.

Итог: регистрация в стороннем клиенте возможна, но Telegram вправе отказать — заранее не узнать, для каких номеров.

## Решение

- Регистрацию оставляем в скоупе v0.5, но как «по возможности»: шаг `AuthorizationStateWaitRegistration` получает экран (имя, фамилия, условия использования, согласие), вызов — `registerUser`.
- Отказ Telegram (`PHONE_NUMBER_APP_SIGNUP_FORBIDDEN` на шаге номера) показывается понятным текстом: создать аккаунт в официальном приложении и войти здесь.
- Обходных путей (чужие `api_id`, имитация официального клиента) не делаем: это нарушает правила Telegram для разработчиков.

## Последствия

- Работоспособность для конкретного номера проверяется только на устройстве; отказ — штатный сценарий, а не баг.
- Если Telegram полностью закроет регистрацию для сторонних `api_id`, экран останется недостижимым, но безвредным; тогда — убрать из PRODUCT.md.
